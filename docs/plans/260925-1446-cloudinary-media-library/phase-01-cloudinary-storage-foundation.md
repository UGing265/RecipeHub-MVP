# Phase 1 — External image foundations

## Context

- Parent: [Cloudinary media library and AI image-candidate demo](./plan.md)
- Existing: `ImageStorageService` validates extension, size, and magic bytes then returns a local filename.
- References: Cloudinary `.NET` `UploadAsync` returns `PublicId`/`SecureUrl`; Cloudflare Workers AI REST API runs `@cf/black-forest-labs/flux-1-schnell` for fast, zero-cost edge diffusion.

## Overview

Configure two server-only integrations: Cloudinary stores accepted assets; Cloudflare Workers AI returns candidate image bytes via standard HTTP. Neither integration is callable from Razor/JavaScript or test code.

**Priority:** P1  
Status: Completed  
**Estimate:** 4h

## Requirements

- Cloudinary and Cloudflare credentials come only from .NET configuration providers; development uses user-secrets and deployment uses secret-injected environment variables.
- Startup validates configuration before accepting its matching operation. Cloudinary is needed for accepted-media operations; Cloudflare only for candidate generation.
- JPEG, PNG, WebP only; non-empty; maximum 5 MiB; extension and magic bytes must agree for user uploads and returned model bytes.
- Cloudinary receives only validated content and generated public IDs; Cloudflare receives only the server-built prompt via standard HTTP POST.
- Every browser error is Vietnamese/actionable and redacts provider keys, authorization headers, raw prompts, and stack traces.

## Implementation steps

1. Add `CloudinaryDotNet`; restore once and lock resolved version by current repository convention.
2. Bind `CloudinaryOptions` and `CloudflareOptions`; validate required fields. Document only user-secret/environment setup:
   ```powershell
   dotnet user-secrets set "Cloudinary:CloudName" "..."
   dotnet user-secrets set "Cloudinary:ApiKey" "..."
   dotnet user-secrets set "Cloudinary:ApiSecret" "..."
   dotnet user-secrets set "Cloudflare:AccountId" "..."
   dotnet user-secrets set "Cloudflare:ApiToken" "..."
   ```
3. Isolate current extension/length/header checks into a validator usable for both `IFormFile` uploads and server-generated byte streams. Never trust `ContentType` alone.
4. Define `StoredImage` and change storage interface to receive validated stream metadata; `DeleteAsync` accepts persisted public ID only.
5. Implement Cloudinary upload with `Folder = "recipe-hub/media"` and destroy through `DeletionParams`; map provider errors to typed internal failures.
6. Define `IAiImageGenerator.GenerateAsync(prompt)` returning image bytes plus MIME metadata. Implement it with Cloudflare Workers AI REST API running `@cf/black-forest-labs/flux-1-schnell`, no model selector, and cancellation timeout.
7. Register fake seams; tests prove invalid image data causes zero Cloudinary calls and Cloudflare failure returns no candidate bytes.

## Success criteria

- Valid user/generated image bytes map to typed image metadata without leaking provider internals.
- Cloudflare credentials never appear in form markup, browser JavaScript, or client responses.
- Generated candidate bytes are validated before any temporary-file write or Cloudinary upload.
- Tests use fakes only; no Cloudinary/Cloudflare credential or network dependency.

## Risks and controls

| Risk | Control |
|---|---|
| Real API call in test suite | inject fakes; tests never require credentials. |
| Browser MIME spoof | magic-byte inspection remains mandatory. |
| Secret committed | user-secrets/environment only; scan config before merge. |
| Cloudflare AI quota/network unavailable | show candidate-generation error; manual real-image workflow remains usable. |
