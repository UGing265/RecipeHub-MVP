# Phase 03 — Extract Recipe Image Workflow

## Context

Plan: [`plan.md`](./plan.md)

`Pages/Recipes/Edit.cshtml.cs` currently coordinates prompt translation, image generation, draft persistence, recipe/step updates, acceptance, and cancellation. Extract only AI image lifecycle behavior. Do not move unrelated recipe CRUD.

## Pre-edit mapping

Before extraction, map and retain behavior for:

- `OnPostGenerateFinalAiImageAsync`;
- `OnPostGenerateAiImageAsync`;
- `OnPostRegenerateAiImageAsync`;
- draft acceptance handler(s);
- draft cancellation handler(s);
- helper methods shared by those handlers;
- final-product versus step-image ownership checks;
- transaction and cleanup behavior;
- validation and user-visible error messages.

## Target API

Introduce `Services/Recipes/RecipeImageService.cs` with operations aligned to user behavior, not HTTP handler names. Exact DTO shape should minimize Razor coupling. Expected capabilities:

```text
GenerateFinalProductDraftAsync
GenerateStepDraftAsync
RegenerateDraftAsync
AcceptDraftAsync
CancelDraftAsync
```

The service may use focused request/result records where needed. Do not pass `PageModel`, `ModelState`, `TempData`, `HttpContext`, or `IActionResult` into the service.

## Responsibility boundary

### PageModel retains

- form binding;
- authorization/page ownership entry checks already belonging to the page;
- request cancellation token retrieval;
- ModelState/TempData presentation;
- redirects and rendered responses.

### RecipeImageService owns

- loading and validating recipe/step/draft targets needed by the image lifecycle;
- building/translating prompt through existing collaborators;
- invoking the image generator;
- storing temporary draft bytes and draft metadata;
- accepting/canceling drafts;
- maintaining current cleanup and transactional invariants.

## Extraction rules

- Preserve existing generator interface in this phase.
- Preserve current Cloudflare-only behavior.
- Preserve exact draft lifecycle and ownership checks.
- Do not add provider branching yet.
- Do not change prompt wording.
- Remove obsolete PageModel helpers after every caller moves; no forwarding shim.

## Tests

Update existing recipe final-image lifecycle tests to invoke the observable page/service path according to current conventions. Keep consumer-visible assertions:

- valid target creates one generated draft;
- accepted draft becomes the correct recipe/step media;
- rejected/canceled draft cannot be accepted;
- a draft cannot be attached to the wrong recipe or step;
- invalid generated bytes do not persist a usable draft;
- final-product and step flows remain distinct.

Avoid tests that only assert one method forwards arguments to another.

## Smoke proof

Run the application and exercise one current Cloudflare generation through the Razor form, then accept or cancel the draft. Observe the page state and stored media/draft outcome.

- [ ] No unrelated recipe CRUD moved.
- [ ] Current Cloudflare user behavior remains intact.
- [ ] Existing lifecycle invariants remain covered.
